2 — SIEM

Les systèmes de détection traditionnels

Le Security Information and Event Management (SIEM) est la pierre angulaire technologique historique de la surveillance de sécurité. Il collecte, normalise et corrèle les logs provenant de sources hétérogènes.

Les 3 piliers du SIEM classique

📥
1. Collection
Agrégation centralisée de millions d'événements bruts provenant de toutes les sources du SI.
🔄
2. Normalisation
Transformation de formats disparates (syslog, CEF, JSON, LEEF…) en schéma unifié et exploitable.
🔗
3. Corrélation par règles
Algorithmes déterministes. Ex : "5 échecs de connexion + 1 succès = Bruteforce". Logique booléenne.

Limites opérationnelles

Limite 01
Fatigue d'alerte
40% des alertes jamais traitées. Un analyste Tier 1 examine 500+ alertes/jour dont 95% non critiques.
Limite 02
Cécité face à l'inconnu
Réactifs et rétrospectifs. Attaque zéro-day, APT, mouvement latéral lent = aucune alerte.
Limite 03
Vitesse d'investigation
Analyse manuelle : 5–20 minutes par incident. L'attaquant a déjà pivoté ou exfiltré.
Limite 04
Coût de propriété
SIEM entreprise : 100k€+ annuels en licences seules. ROI faible si peu d'incidents évités.
3 — SOC

Le SOC : une approche organisationnelle

Un Security Operations Center (SOC) est une fonction organisationnelle complète intégrant personnes, processus et technologies pour détecter, enquêter et répondre aux incidents 24h/7j.

Matrice de Maturation SOC (2025 — SANS Survey)

Niveau 1 — Basique
Alertes & triage manuel
Alert fatigue chronique, temps de réponse lent, réaction manuelle à chaque incident.
Niveau 2 — Géré
Playbooks basiques
Automatisation partielle. 85% incident response déclenché par alertes — posture réactive.
Niveau 3 — Mature
AI/ML + SOAR + UEBA
Threat hunting régulier, behavioral modeling, anomaly detection par ML.
Niveau 4 — Intelligence-Driven ★
Adversary profiling
TTP-based hunting, full automation avec tactical intel. Leaders 2025 : niveaux 3–4.
4 — Intelligence Artificielle

L'apport de l'IA à la détection d'intrusions

L'IA ne remplace pas les outils existants, mais agit comme une couche d'intelligence supplémentaire venant transformer la manière dont les données sont analysées et les décisions prises.

Techniques opérationnelles

🎯
Apprentissage Supervisé
Entraînement sur données étiquetées. Cas d'usage : détection de malware, classification.
🔍
Apprentissage Non-Supervisé
Détection d'anomalies statistiques sans étiquettes. Cas d'usage : comportements inhabituels.
🧬
Deep Learning
Réseaux neuronaux multi-couches.
Réduit faux positifs de 99% vs IDS classiques
👤
UEBA
Baselines ML de comportement "normal", détecte les écarts.
+67% détection insider threats

6 — POC

Proof of Concept — Enrichissement IA des alertes Wazuh

Objectif : transformer des alertes techniques générées par Wazuh en analyses compréhensibles par un analyste SOC, grâce à un script Python interfacé avec un LLM via API.
Pipeline : Attaque SSH → Alerte enrichie par IA
1
Attaque par force brute SSH lancée depuis Kali Linux
2
Agent Wazuh transmet les événements au Wazuh Manager
3
Wazuh applique ses règles → génère alerte JSON
4
Script Python envoie l'alerte à l'API LLM (gpt-4o-mini)
5
L'IA retourne une analyse structurée → enregistrée dans ai_enrich.log
Python 3 — ai_enrich.py

7 — Résultats

Alerte enrichie par l'IA

Sortie IA — Analyse enrichie
1. Type d'attaque : Tentative d'accès non autorisé via SSH

2. Niveau de risque : Modéré — peut indiquer tentative d'intrusion

3. Ce qui s'est produit : Authentification SSH échouée sur 192.168.72.138.

4. Actions immédiates :
   - Vérifier journaux SSH pour identifier l'origine
   - Bloquer l'IP source si suspecte ou tentatives répétées
   - Informer l'équipe de sécurité

5. Recommandations long terme :
   - Listes blanches IP autorisées pour SSH
   - Authentification par clé publique
   - Surveiller régulièrement les journaux d'accès
