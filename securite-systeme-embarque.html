01

Contexte & Matériel

L'objectif de ce TP était d'aborder la sécurité des objets connectés par la pratique, en attaquant une carte volontairement vulnérable, la DVID (Damn Vulnerable IoT Device). Chaque module cible une surface d'attaque différente d'un système embarqué : l'interface de debug, le firmware, la radio et l'application web. L'enjeu est de comprendre comment un attaquant extrait des secrets d'un composant matériel que l'on croit fermé.

02

Module 1 — Liaison UART

Le premier module établit une communication série UART avec la carte : identification des broches, câblage croisé (RX ↔ TX) et flashage du firmware avec avrdude via le programmeur USBasp. Une fois la liaison ouverte, l'écoute du port série permet de récupérer les messages émis par le microcontrôleur, et donc un premier flag.

Principe clé : une interface de debug (UART) laissée accessible est une porte d'entrée directe sur le fonctionnement interne d'un équipement embarqué.
03

Module 2 — Analyse de firmware

Le cœur du TP : extraire le firmware de la carte, puis l'analyser pour en tirer des secrets. Plusieurs techniques sont mises en œuvre, de la plus simple à la plus avancée.

2.1 — FIND THE DATASHEET
Écoute série
Identification du bon pin de sortie et lecture du mot de passe transmis sur la liaison série via un script Python.
2.2 / 2.3 — HARDCODED
Secrets en dur
Dump du firmware avec avrdude, puis extraction des chaînes avec strings pour révéler un mot de passe stocké en dur.
2.4 — EEPROM
Simulation AVR
Analyse du dialogue firmware ↔ EEPROM en simulation avec SimAVR et visualisation des signaux dans GTKWave.
2.5 — GARGOYLE
Reverse binwalk
Extraction du système de fichiers d'un firmware avec binwalk, puis recherche des secrets dans /etc/shadow.
Enseignement : un firmware embarque souvent bien plus que du code — identifiants en clair, clés, systèmes de fichiers entiers — accessibles dès lors qu'on peut le dumper.
04

Module 3 — Bluetooth BLE

Ce module explore la surface radio de l'objet connecté via le Bluetooth Low Energy, en lecture puis en écriture sur une caractéristique GATT spécifique (0000ffe1), à l'aide d'une clé BLE et de l'application nRF Connect.

ModeActionRésultat
RX (lecture)Lecture de la caractéristique BLE / champ « Device Name »Récupération du mot de passe (flag)
TX (écriture)Écriture d'un mot de passe dans la caractéristiqueDéblocage de l'OTP affiché par la carte
La radio BLE est une surface d'attaque à part entière : des caractéristiques GATT mal protégées exposent lecture et écriture de données sensibles à portée radio.
05

Module 4 — Interface web embarquée

Beaucoup d'objets connectés exposent une interface web d'administration. Ce module cible les vulnérabilités web classiques de cette interface.

Injection SQL (SQLi)

La détection se fait par une simple apostrophe provoquant une erreur SQL. L'exploitation, par requêtes UNION, permet d'énumérer les tables et colonnes puis d'extraire les comptes utilisateurs, dont les condensats de mots de passe — ensuite cassés via une base de hachages (CrackStation).

CSRF (Cross-Site Request Forgery)

Le formulaire de changement de mot de passe ne comporte aucun jeton anti‑CSRF : une page piégée envoyant une simple requête vers l'application, ouverte par un utilisateur authentifié, suffit à modifier son mot de passe à son insu.

L'interface web d'un objet connecté hérite de toutes les failles du web classique — et les conséquences sont physiques quand elle pilote un équipement.
06

Bilan & compétences

Ce TP m'a fait parcourir l'ensemble des surfaces d'attaque d'un système embarqué, du niveau matériel (UART, firmware, EEPROM) au niveau applicatif (BLE, web). C'est une approche très concrète de la sécurité IoT, qui montre pourquoi la défense doit couvrir toute la chaîne — du silicium jusqu'à l'interface utilisateur.
