01

Contexte & Objectifs

Avec l'augmentation des cyberattaques et des menaces réseau, il est essentiel de mettre en place des solutions de surveillance et de protection avancées. Ce projet vise à renforcer la sécurité du réseau en déployant une infrastructure de détection et de réponse aux intrusions basée sur Wazuh.

03

Déploiement Wazuh

Déploiement depuis l'OVA officielle Wazuh (Manager + Indexer + Dashboard) sur VMware avec allocation de ressources adaptées.

bash — Installation Agent Windows
NET START WazuhSvc
# Confirmation : Le service Wazuh démarre / a démarré
bash — Installation Agent Ubuntu
sudo systemctl daemon-reload
sudo systemctl enable wazuh-agent
sudo systemctl start wazuh-agent
Résultat : 2 agents actifs visibles dans le dashboard Wazuh — Windows (192.168.72.145) et Ubuntu (192.168.72.147).
04

Règles Personnalisées & Active Response

Configuration du blocage automatique des attaques SSH brute force via le script firewall-drop d'Active Response.

xml — /var/ossec/etc/ossec.conf
<active-response>
  <command>firewall-drop</command>
  <location>local</location>
  <rules_id>5763</rules_id>
  <timeout>180</timeout>
</active-response>

Test — Attaque SSH Brute Force (Hydra)

bash — Simulation depuis Kali
hydra -l agent -P /usr/share/wordlists/rockyou.txt 192.168.72.147 ssh
✅ Résultat : Wazuh détecte l'attaque et bloque automatiquement l'IP de l'attaquant via iptables — confirmé dans le dashboard (règle 5763).
05

Intégration Suricata

Installation de Suricata v6.0.8 sur l'agent Ubuntu avec les règles Emerging Threats pour la détection des menaces réseau. Intégration avec Wazuh via les logs /var/log/suricata/eve.json.

bash — Installation Suricata
sudo add-apt-repository ppa:oisf/suricata-stable
sudo apt-get install suricata -y
cd /tmp/ && curl -LO https://rules.emergingthreats.net/open/suricata-6.0.8/emerging.rules.tar.gz
sudo tar -xvzf emerging.rules.tar.gz && sudo mv rules/*.rules /etc/suricata/rules/
xml — Configuration agent Wazuh
<ossec_config>
  <localfile>
    <log_format>json</log_format>
    <location>/var/log/suricata/eve.json</location>
  </localfile>
</ossec_config>
Note : La détection ARP Spoofing via Ettercap n'a pas pu être validée malgré la règle configurée. La détection Nmap scan fonctionne correctement.
06

Intégration VirusTotal

Intégration de l'API VirusTotal avec Wazuh pour l'analyse automatique des fichiers suspects détectés par FIM (File Integrity Monitoring). Un script Python remove-threat.py automatise la suppression des fichiers malveillants.

xml — Configuration VirusTotal
<integration>
  <name>virustotal</name>
  <api_key>[API_KEY]</api_key>
  <group>syscheck</group>
  <alert_format>json</alert_format>
</integration>

<syscheck>
  <directories realtime="yes">C:\Users\pc client\Downloads</directories>
</syscheck>
✅ Test EICAR : Le fichier de test a été détecté par VirusTotal (65 moteurs) et automatiquement supprimé par remove-threat.exe via Active Response.
07

Détection des Attaques Web

Utilisation de l'application vulnérable DVWA sur Ubuntu pour tester la détection et la réponse aux attaques web. Wazuh analyse les logs Apache via Active Response.

SQLi — Injection SQL

bash — Simulation SQLi
curl -XGET "http://192.168.72.147/DVWA/vulnerabilities/sqli/?id=SELECT+*+FROM+users"
# → Wazuh détecte (règle 31103) et bloque l'IP attaquante (timeout 180s)

XSS — Cross-Site Scripting

bash — Simulation XSS
curl -X GET "http://192.168.72.147/DVWA/vulnerabilities/sqli/?id=<script>alert('XSS')</script>"
# → Wazuh détecte (règle 31105) et bloque l'IP attaquante

Fuzzing Web — Gobuster

bash — Simulation fuzzing
gobuster dir -u http://192.168.72.147/ -w /usr/share/wordlists/dirbuster/directory-list-2.3-small.txt
# → Wazuh détecte les erreurs 404 répétées (règle 31101) et bloque l'IP
